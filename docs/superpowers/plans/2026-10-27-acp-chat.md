# ACP Agent Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- Chat with any installed ACP agent from the left pane.
- Detect agents and set up adapters in one click.
- Stream messages, thoughts, tool calls and plans.
- Answer permission requests in chat.
- Attach the timeline selection (including the scene's source file) to prompts.
- Auto-commit every agent turn that changed files.

**Architecture:**
- **Rust:**
  - `agents/`: the registry data file, login-shell PATH resolution, detection, adapter install, launch specs and settings.
  - `acp/`: a hand-rolled newline-delimited JSON-RPC 2.0 connection over any `AsyncRead`/`AsyncWrite`, so it can be tested with `tokio::io::duplex`.
  - On top of that, an ACP client and a session manager that owns the agent process, scopes `fs/*` to the project, and runs the turn lifecycle with git commits before and after each turn.
- **Frontend:**
  - Receives `agent://*` events.
  - A pure reducer turns ACP `session/update` payloads into chat items.
  - Svelte components render them behind an injected `AgentApi`, so tests run without Tauri.

**Tech Stack:**
- existing foundation
- `tokio` (process, io-util, sync, macros, rt; already in Tauri's tree, added explicitly)

No ACP crate: the surface we use is small and the crate API changes quickly (ruling below).

**Spec:** `docs/superpowers/specs/2026-10-27-liosvideo-design.md`, covering:
- §8.1 detection and setup
- §8.2 session
- §8.4 targeted revisions
- §6 chat pane
- §12 auto-commit per turn and manual edits before a turn

- **Protocol (v1):**
  - `initialize` → `{protocolVersion: 1, clientCapabilities: {fs: {readTextFile, writeTextFile}, terminal}, clientInfo}`
  - `session/new` → `{cwd, mcpServers}` returns `{sessionId}`
  - `session/prompt` → `{sessionId, prompt: ContentBlock[]}` returns `{stopReason}`, one of `end_turn | max_tokens | max_turn_requests | refusal | cancelled`
  - `session/cancel` is a notification.
  - `session/update` → `{sessionId, update: {sessionUpdate: agent_message_chunk | agent_thought_chunk | user_message_chunk | tool_call | tool_call_update | plan | …}}`
  - `session/request_permission` → `{sessionId, toolCall, options: [{optionId, name, kind: allow_once | allow_always | reject_once | reject_always}]}`, answered with `{outcome: {outcome: "selected", optionId} | {outcome: "cancelled"}}`
  - `fs/read_text_file {sessionId, path (absolute), line?, limit?}` returns `{content}`
  - `fs/write_text_file {sessionId, path, content}` returns `{}`
  - Auth required is error code `-32000`; then call `authenticate {methodId}`.
  - Auth methods come from the `initialize` result: `authMethods: [{id, name, description?, type?}]`.

## Global Constraints

- **Agent support (§8.1):** works with any installed ACP agent. The app installs only adapters, never agents. Agents that aren't installed are shown greyed out with an install link.
- **PATH (§8.1):** GUI apps don't inherit the shell PATH, so resolve the login shell's PATH.
- **Credentials (§8.1):** the app never sees agent credentials. Auth-required states are surfaced with the agent's methods.
- **Sessions (§8.2):** one ACP session per project, with `cwd` set to the project folder. File access is scoped to the project folder.
- **Commits (§12):**
  - Before each turn, commit pending outside edits as "Manual edit".
  - After a turn that changed files, commit with a summary of the user prompt.
  - Only when history is `Enabled` and `can_auto_commit` holds (Project + Git plan).
- **Selection context (§8.4):** composition file, scene id, scene source file path, object path, time range and current playhead time.
- Every path the agent sends goes through `resolve_in_project`, after converting it from absolute to project-relative.

## Review Focus

1. **The agent process fails to start, exits mid-turn, or needs auth.** The status goes to `error`, `exited` or `auth_required`, with the tail of stderr (last 20 lines). Pending requests are rejected, and the UI never stays stuck on "working". Tests in Tasks 3, 4 and 6.
2. **The agent asks for files outside the project** (`/etc/passwd`, a symlink escape, a relative path, `..`). It gets a JSON-RPC error, and nothing is read or written. Test in Task 3.
3. **Cancel while a permission card is pending.** The request is answered `cancelled`, the card is disabled, the turn ends with `cancelled`, and files changed so far are still committed. Tests in Tasks 4 and 6.
4. **Noisy, slow or non-zsh login shells.** The PATH is extracted between markers, with a 5 s timeout and fallback dirs appended. Test in Task 1.
5. **Long, chunk-heavy agent output.** Chunks coalesce into one chat item per message, never one item per chunk. A second prompt while a turn is running is rejected. Tests in Tasks 4 and 6.

- `rpc.rs`:
  - ```rust
    #[derive(Debug, Clone, Serialize, Deserialize)] pub struct RpcError { pub code: i64, pub message: String, pub data: Option<Value> }
    pub trait Handler: Send + Sync + 'static {
        fn request(&self, method: String, params: Value) -> BoxFuture<'static, Result<Value, RpcError>>;
        fn notification(&self, method: String, params: Value);
    }
    pub struct Connection { .. } // Clone
    impl Connection {
        pub fn start<R: AsyncRead + Unpin + Send + 'static, W: AsyncWrite + Unpin + Send + 'static>(reader: R, writer: W, handler: Arc<dyn Handler>) -> Connection;
        pub async fn request(&self, method: &str, params: Value) -> Result<Value, RpcError>;
        pub async fn notify(&self, method: &str, params: Value) -> Result<(), RpcError>;
        pub async fn closed(&self); // resolves when the reader hits EOF
    }
    ```
  - Messages are one JSON object per line.
  - Incoming requests run concurrently (spawned) and reply with `result` or `error`.
  - Unparseable lines are ignored.
  - On EOF every pending request fails with `RpcError { code: -32099, message: "Agent exited" }`.
  - `BoxFuture` is a local alias, `Pin<Box<dyn Future<Output = T> + Send>>`; no `futures` crate.

  - `pub const PROTOCOL_VERSION: u64 = 1; pub const AUTH_REQUIRED: i64 = -32000;`
  - `pub struct AgentInfo { pub auth_methods: Vec<Value>, pub load_session: bool, pub image: bool, pub embedded_context: bool, pub raw: Value }`
  - `pub enum SessionError { AuthRequired(Vec<Value>), Rpc(RpcError) }`
  - `pub struct AcpClient { conn: Connection }` with:
    - `initialize()`: sends `clientCapabilities {fs: {readTextFile: true, writeTextFile: true}, terminal: false}` and `clientInfo {name: "liosvideo", title: "liosvideo", version}`.
    - `new_session(cwd: &Path, mcp_servers: Vec<Value>) -> Result<String, SessionError>`
    - `authenticate(method_id)`
    - `prompt(session_id, blocks: Vec<Value>) -> Result<String /*stopReason*/, RpcError>`
    - `cancel(session_id)`
  - `pub trait ClientEvents: Send + Sync + 'static { fn update(&self, update: Value); fn permission(&self, params: Value) -> BoxFuture<'static, Value /*outcome object*/>; }`
  - `pub struct ClientHandler { root: PathBuf, events: Arc<dyn ClientEvents> }` implements `Handler`:
    - `fs/read_text_file`:
      - Converts the absolute `path` to project-relative by stripping the canonical root, then resolves it with `resolve_in_project`. A relative or outside path gets `RpcError -32602 "path is outside the project"`.

    - `session/request_permission`: returns `{outcome: events.permission(params).await}`.
    - `session/update` notification: `events.update(params.update)`.
    - Any other method: `-32601`.

### Task 4: Session manager, turn lifecycle and commands

**Files:**
- Create: `src/acp/session.rs`
- Modify: `src/lib.rs` (state + commands)

**Interfaces:**
- Consumes: Tasks 1–3; `git::{commit_all, can_auto_commit, history_status, MANUAL_EDIT}`; `project::git_job`.
- Selection context:
  ```rust
  #[serde(rename_all = "camelCase")]
  pub struct SelectionContext {
      composition: String,
      scene_id: String,
      scene_file: Option<String>,
      path: Option<String>,
      start_frame: u32,
      end_frame: u32,
      fps: f64,
      playhead_frame: Option<u32>,
  }
  ```
- `pub fn build_prompt(text: &str, sel: Option<&SelectionContext>) -> Vec<Value>`:
  - Always produces `[{type: "text", text}]`.
  - With a selection, it is followed by a second `text` block (text blocks are baseline for every agent, unlike `resource`). That block starts with `Selected on the timeline (confine edits to this unless asked otherwise):` and has one line each for:
    - `composition: long.ts`
    - `scene: intro (file: scenes/intro.ts)`
    - `object: desktop/terminal` (the path relative to the scene, omitted when there is no path)
    - `time: 1.00s–2.50s (frames 30–75)`
    - `playhead: 1.20s (frame 36)` (when set)
- `pub fn turn_commit_message(prompt: &str) -> String`: the first non-empty line, trimmed and collapsed to single spaces, cut to 72 chars with `…`. An empty prompt gives `"Agent turn"`.
- `pub struct AgentSession` (one per app, for the open project) holds the child process, `AcpClient`, session id, root, agent id, turn state and pending permission senders keyed by request id.
- Turn:
  1. Reject if a turn is active (`"A turn is already running"`).
  2. If history is `Enabled` and `can_auto_commit`, run `commit_all(MANUAL_EDIT)` via `git_job`, emitting `project://committed`.
  3. Emit `agent://turn {state: "started"}`.
  4. `prompt(...)`.
  5. Afterwards, regardless of the stop reason or error, and under the same history condition: `commit_all(turn_commit_message(text))`.
  6. Emit `agent://turn {state: "ended", stopReason?, error?, commit?}`.
- Cancel: send `session/cancel` and answer every pending permission with `{outcome: "cancelled"}`.
- Events:
  - `agent://status {state: "connecting" | "ready" | "auth_required" | "error" | "exited", agentId, message?, authMethods?}`
  - `agent://update {update}`
  - `agent://permission {requestId, toolCall, options}`
  - `agent://turn {...}`
- When the process exits, emit status `exited` with the last 20 stderr lines and fail any active turn.
- Commands, all async:
  - `agent_connect(agent_id: Option<String>)`:
    - Uses the project's agent, else the default, else an error `"Choose an agent first"`.
    - Spawns with `cwd = root`, stdin/stdout piped and stderr captured, then runs `initialize` and `session/new` with `mcpServers: []`.
    - Reconnecting kills the previous process first.
  - `agent_authenticate(method_id)`: authenticates, then retries `session/new`.
  - `agent_prompt(text, selection: Option<SelectionContext>)`
  - `agent_cancel()`
  - `agent_permission_respond(request_id, option_id: Option<String>)`: `None` means cancelled.
  - `agent_disconnect()`
  - Opening another project disconnects the current session.
